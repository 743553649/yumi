## 运行时测试（需刷机验证）

### 阶段一：Bug 修复验证

### 1.1 CLG 配置生效验证
- **操作**: 修改 `config.yaml` 的 `balance` 段，将 `smoothing_up` 改为 `0.30`，保存触发热重载
- **预期**: 日志出现 `clg-config-reloaded`，CLG 升频速度明显变慢
- **验证命令**: `su -c 'logcat | grep clg'`

### 1.2 未知模式 CLG 验证
- **操作**: 打开一个配置为 FAS 模式的游戏
- **预期**: 日志中**不应**出现 `clg-activated`，CLG 不会在 FAS 模式下意外激活

### 1.3 i18n 非法语言标签验证
- **操作**: 在 `config.yaml` 设置 `language: "!!invalid!!"`，重启 yumi
- **预期**: 不 panic，日志回退到英文输出

## 阶段二：FAS 安全加固验证

### 2.1 floor-rescue 验证
- **操作**: 在游戏中将 `perf_floor` 设为 0.40，等待长时间低帧率场景
- **预期**: 日志出现 `floor-rescue` 后，perf 能真正跳到 `perf_cold_boot`（0.85），不被截断回 0.49
- **验证命令**: `su -c 'logcat | grep floor-rescue'`

### 2.2 非法帧率档位验证
- **操作**: 在 `rules.yaml` 的 per-app 中设置 `target_fps: [0, -1, 60]`
- **预期**: 不 panic，0 和 -1 被自动过滤，只保留 60

## 阶段三：CLG 重构验证（重点）

### 3.1 headroom 渐变验证
- **操作**: 日用场景滑动（社交/浏览器），观察 CPU 利用率在 65%~80% 区间
- **预期**: 频率不应出现方波振荡（在 up_threshold 附近反复跳变），应平滑过渡
- **验证命令**: `su -c 'logcat | grep clg-tick-log'`，观察 perf 值变化

### 3.2 滞回带降频验证
- **操作**: 从高负载场景（如应用启动）回落到日用空闲（55%~75% 利用率）
- **预期**: 频率应开始缓慢下降（旧逻辑：util 在 down_threshold 和 up_threshold 之间不降频）

### 3.3 尖峰抑制验证
- **操作**: 观察日志中 util 单次跳变
- **预期**: 单 tick 尖峰（如单核 0↔100%）不会瞬间拉满频率，下一 tick 恢复正常
- **验证命令**: `su -c 'logcat | grep clg-tick-log'`，观察 util 和 perf 变化是否同步

### 3.4 极低负载快速降频验证
- **操作**: 从重负载突然切到空闲（如退出 App 回到桌面）
- **预期**: 频率应在 1-2 个 tick（200-400ms）内快速回落（旧逻辑：等待 3+ tick / 600ms+）

### 3.5 release 恢复验证
- **操作**: 切换模式（如 balance → performance → balance）
- **预期**: 日志出现 `clg-deactivated` 后 governor 恢复为 `performance`，不是 `userspace`
- **验证命令**: `su -c 'logcat | grep -E "clg-deactivated|scaling_governor"'`

### 3.6 热重载验证
- **操作**: 编辑 `config.yaml` 保存触发热重载（不切换模式）
- **预期**: 只出现 `clg-config-reloaded`，不出现完整的 `clg-init` 流程（不重建 sysfs writer）

### 3.7 IPC panic 保护验证
- **操作**: 故意制造异常（如将 config.yaml 格式改为无效 YAML）
- **预期**: 日志出现 `scheduler-ipc-panicked` 而非进程静默死亡
- **验证命令**: `su -c 'logcat | grep panicked'`

## 常用验证命令

```bash
# 实时查看 CLG/FAS 日志
su -c 'logcat | grep -E "clg-|fas-|scheduler-"' 

# 查看当前 CPU 频率
su -c 'cat /sys/devices/system/cpu/cpufreq/policy0/scaling_cur_freq'

# 查看当前 governor
su -c 'cat /sys/devices/system/cpu/cpufreq/policy0/scaling_governor'

# 查看 yumi 进程状态
su -c 'ps -A | grep yumi'

# 查看 yumi 日志文件
su -c 'cat /data/adb/modules/yumi/logs/service.log'
```

1. 在 KernelSU 管理器中禁用 yumi 模块
2. 重启设备
3. 或者刷入旧版本 zip 覆盖安装
