# 日志精简计划

## 问题
INFO 级别日志中混入了大量高频操作事件（触摸、档位切换等），导致真正重要的状态变更被淹没，整体看起来杂乱。不符合 AGENTS.md 的日志规范——`info!` 应只用于"关键状态变化"。

## 主要噪音源

| 文件 | 日志 | 触发频率 | 问题 |
|------|------|---------|------|
| `touch_boost/controller.rs:76` | `touch-boost-start` | **每次触摸** | 刷抖音/滑列表时疯狂刷 |
| `touch_boost/controller.rs:82` | `touch-boost-release` | **每次松手** | 同上 |
| `touch_boost/controller.rs:126` | `touch-boost-recovered` | **每次恢复** | 同上 |
| `fas/gear_state.rs:72` | `fas-gear-switch` | 负载波动时 | 档位升降是常规操作 |
| `fas/gear_state.rs:144` | `fas-low-perf-upgrade` | 同上 | 同上 |
| `fas/gear_state.rs:193` | `fas-downgrade-boost` | 同上 | 同上 |
| `fas/gear_state.rs:207` | `fas-boost-expired` | 同上 | 同上 |

## 修改方案

### 1. TouchBoost 3条日志：`info!` → `debug!`
**文件**: `src/touch_boost/controller.rs`

每次触摸都打日志，属于"频繁事件"，不符合 info 级别定义。`debug` 已在 L22 导入，只需改日志调用。

```
L76:  info!  → debug!  (touch-boost-start)
L82:  info!  → debug!  (touch-boost-release)
L126: info!  → debug!  (touch-boost-recovered)
```

### 2. StillDive 调试日志：合并到门控块
**文件**: `src/scheduler/cpu_load_governor.rs`

当前 L358 的 `debug!("[StillDive] max_util=...")` 每 200ms 触发，即使 DEBUG 级别也太吵。删除此行，将 StillDive 状态摘要合并到已有的 `log_counter % 25` 门控块中（~5秒一次），跟 `clg-tick-log` 对齐。

```
L358: 删除每次输出的 debug!("[StillDive] ...")
在 log_counter % 25 块中新增: if let Some(ref sd) = self.still_dive { ... }
```

### 3. FAS 档位日志：`info!` → `debug!`
**文件**: `src/scheduler/fas/gear_state.rs`

档位升降是调度器常规操作，不算"关键状态变化"。`use log::info` → `use log::debug`，4处调用 `info!` → `debug!`。

```
L18:  use log::info  →  use log::debug
L72:  info! → debug!  (fas-gear-switch)
L144: info! → debug!  (fas-low-perf-upgrade)
L193: info! → debug!  (fas-downgrade-boost)
L207: info! → debug!  (fas-boost-expired)
```

## 不动的日志（保留 info!）

| 日志 | 理由 |
|------|------|
| `clg-still-enter/exit` | 模式切换，真正关键 |
| `idle-dive-*` 状态变更 | 省电模式切换，低频 |
| `fas-loading-start/exit` | 加载状态变化，低频 |
| `fas-app-switch` | 应用切换，频率适中 |
| `touch-boost-config-reloaded` | 配置重载，罕见 |
| `touch-boost-init` | 初始化，一次性 |
| 所有 `warn!/error!` | 已经是正确级别 |

## 涉及文件

1. `src/touch_boost/controller.rs` — 3 处 `info!` → `debug!`
2. `src/scheduler/cpu_load_governor.rs` — 删除 L358 debug，合并到门控块
3. `src/scheduler/fas/gear_state.rs` — import 改 `debug`，4 处 `info!` → `debug!`

## 验证

- `cargo check` 编译通过
- INFO 级别下：触摸不刷屏，档位切换不输出
- DEBUG 级别下：StillDive 状态约 5 秒输出一次
