# IdleDive 和 StillDive 优化计划

## 概述

基于对 `src/idle_dive/` 和 `src/scheduler/cpu_load_governor.rs` 的深入分析，识别出以下优化点：

1. **Bug修复**: StillDive 状态机 `low_ticks` 未重置
2. **性能优化**: sysfs 写入的冗余 chmod 操作
3. **逻辑优化**: 配置热重载丢失运行时状态
4. **日志优化**: log_cooldown 机制和 i18n 规范
5. **代码质量**: 提取公共方法、增加文档

---

## 优化任务清单

### 任务 1: 修复 StillDive low_ticks 未重置的 Bug (高优先级)

**问题**: 模式切换时 `low_ticks` 未重置，可能导致 exit 后立即 re-enter dive。

**文件**: `src/scheduler/cpu_load_governor.rs`

**修改点**:
- 第 380 行后追加: `sd.low_ticks = 0;`
- 第 393 行后追加: `sd.low_ticks = 0;`

**验证**: 运行 `cargo check` 确保编译通过。

---

### 任务 2: 优化 sysfs 写入的冗余 chmod 操作 (高优先级)

**问题**: `write_to_file()` 每次写入都执行 `set_permissions()`，导致每次状态转换约 21-27 次无用 chmod 系统调用。

**文件**: `src/utils.rs`

**修改点**:
- 第 37-43 行: 移除 `set_permissions()` 调用，改为只在初始化时检查权限
- 或者: 添加 `write_to_file_nochmod()` 方法用于 sysfs 写入

**验证**: 运行 `cargo check` + 手动测试 sysfs 写入是否正常。

---

### 任务 3: StillDive 配置热重载保留运行时状态 (中优先级)

**问题**: `reload_config()` 创建新的 `StillDiveRuntime`，丢失所有运行时状态。

**文件**: `src/scheduler/cpu_load_governor.rs`

**修改点**:
- 第 296-306 行: 改为更新 `runtime.config` 而非创建新实例
- 当阈值参数变化时选择性重置对应计数器

**代码示例**:
```rust
pub fn reload_config(&mut self, gov_cfg: &CpuLoadGovernorConfig, still_dive: Option<StillDiveConfig>) {
    self.cfg = gov_cfg.clone();
    self.normalize_cfg();
    
    match (&mut self.still_dive, still_dive) {
        (Some(ref mut runtime), Some(mut new_config)) => {
            new_config.normalize();
            // 当阈值变化时重置对应计数器
            if runtime.config.enter_threshold != new_config.enter_threshold
                || runtime.config.enter_ticks != new_config.enter_ticks {
                runtime.low_ticks = 0;
            }
            if runtime.config.exit_threshold != new_config.exit_threshold
                || runtime.config.exit_ticks != new_config.exit_ticks {
                runtime.high_ticks = 0;
            }
            runtime.config = new_config;
        }
        (None, Some(mut new_config)) => {
            new_config.normalize();
            self.still_dive = Some(StillDiveRuntime::new(new_config));
        }
        (Some(_), None) => {
            self.still_dive = None;
        }
        (None, None) => {}
    }
}
```

**验证**: 运行 `cargo check` + 测试配置热重载是否保留状态。

### 任务 4: IdleDive log_cooldown 改为基于时间的冷却 (中优先级)

**问题**: 当前 log_cooldown 使用 update 次数（约 25ms），冷却期太短。

**文件**: `src/idle_dive/controller.rs`

**修改点**:
- 第 41 行: 将 `log_cooldown: u32` 改为 `last_log_time: Instant`
- 第 79-81 行: 移除递减逻辑
- 第 144-151 行: 改为检查时间间隔（1-2秒）

**代码示例**:
```rust
// 字段声明
last_log_time: Instant,

// transition_to() 中
if self.last_log_time.elapsed().as_secs() >= 1 {
    match new_state {
        IdleDiveState::Normal => info!("{}", t("idle-dive-exit")),
        IdleDiveState::Diving => info!("{}", t("idle-dive-enter")),
        IdleDiveState::DozeDiving => info!("{}", t("idle-dive-enter-dozed")),
    }
    self.last_log_time = Instant::now();
}
```

**验证**: 运行 `cargo check` + 测试日志输出频率。
